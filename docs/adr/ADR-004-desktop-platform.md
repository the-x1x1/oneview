# ADR-004 — Desktop platform: Electron + Vite + React, Windows x64 first

Status: Accepted · 2026-09-21 · Package: `apps/desktop`, `@worldview/ipc-contract`

## Decision

- Electron (current stable) with `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, strict CSP, no `eval`, no remote module. Main process hosts the runtime (providers, state, history, offline, cameras, updater); the renderer hosts React + the render adapters.
- IPC is an allowlisted, typed request catalogue (`WorldRequests`) and event catalogue (`WorldEvents`) in `@worldview/ipc-contract`; the preload exposes `window.worldview` implementing `WorldClient`. The same interface is implemented in-process for browser development and demo mode, so the shell never branches on platform.
- Secrets use Electron `safeStorage` (DPAPI on Windows) via `credentials.set`; the renderer never receives values.
- Packaging: electron-builder → `WorldView-Setup-x.y.z.exe` (NSIS) and `WorldView-Portable-x.y.z.zip`. Node 22 LTS, pnpm 10.28.0 pinned.
- Tests use Node's built-in `node:test` runner through `tsx` (zero framework dependencies; the same runner GEV uses), grouped by directory convention (`tools/dev/run-tests.mjs`).
- 2026-09-21 amendment (first-run state): whether the welcome flow has been completed is persisted settings state (`AppSettings.firstRunCompleted`), not renderer storage. The interface has no durable store of its own — `localStorage` is unavailable under the sandbox, is per-origin rather than per-installation, and would disagree with the settings file after a reset or a portable/installed switch — so `finishWelcome()` writes through `settings.set` like every other preference and the runtime remains the single source of truth.
- 2026-09-23 amendment (memory in Diagnostics): `DiagnosticsSnapshot` gains an optional `memory` (`MemorySnapshot`: working set per process kind from Electron's `app.getAppMetrics()`, the main process's JS heap, and the totals of the last six hours at one sample per ten minutes). The main process samples it (`memory-monitor.ts`) and writes each sample to the application log as `process memory`; a runtime without process metrics leaves it out. The QA checklist's "memory in Diagnostics is stable" could not be checked before this.
- 2026-09-23 amendment (watch-zone quiet hours): `WatchZone` gains an optional `quietHours` (`{ start, end }`, "HH:MM" in this machine's time zone; `start` after `end` spans midnight). During them a zone's hits raise their events and feed items as before but interrupt — toast, desktop notification — only at SEVERE or above (`mayInterrupt`). The runtime now also honours `notifications.inApp`, which it had ignored.
- 2026-09-23 amendment (watch-zone escalation): `WatchZone` gains an optional `desktopMinimumSeverity` — desktop notifications only from that severity up, in-app and the feed keep the rest. The evaluator also re-notifies inside its 6 h dedupe window when the same subject comes back more severe than it was last notified at (a watch upgraded to a warning), titled "— now Severe" with `escalatedFrom` in the entry event's properties.
- 2026-09-23 amendment (pack signatures): `WorldPackSummary` gains an optional `signature` (`WorldPackSignatureSummary`: `unsigned | signed | trusted | unchecked | invalid`, the key id, the publisher's name, a reason) and `OfflineStatus` an optional `trust` (`requireTrusted` and the publishers' names, key ids and dates — never their keys). Four requests manage it: `offline.trustPublisher` (the signer of an installed, verified pack, under a name the operator types), `offline.importPublisher` (a `.worldpack-pub` file through the open dialog, read and parsed in the main process), `offline.removePublisher` and `offline.setRequireTrusted` (ADR-007). `WorldPackSummary` also gains optional `createdAt` and `expiresAt` from the manifest, so Settings can say how old a pack is and when its publisher says it goes out of date.
- 2026-09-23 amendment (raster overlays): request `overlays.list` (`RasterOverlay[]` from every running provider) and event `overlays.changed` (`{ overlays }`, the full list on any change). The store keeps them in `sources.overlays`; the map host hands them to the renderer host, which replays them into whichever renderer is active and any built later (ADR-008).
- 2026-09-24 amendment (connector definitions, for phase `source-health-ui`): requests `sources.definitions.list` (`DefinitionsListing`: the operator's folder, or null without one, and every definition file with its id, connector, enabled state, whether it is shipped, and its problems and notes), `sources.definitions.reload` (the listing plus the ids added, removed and restarted), `sources.definitions.setEnabled { file, enabled }` (persisted as `sources.setEnabled` is), `sources.definitions.openFolder` (main opens the runtime's folder with `shell.openPath`; the path never comes from the renderer), `sources.definitions.draft { url }` → `DefinitionDraft` (`definition`, `connector`, `notes`, `todo`, `validation`; the fetch runs in main) and `sources.definitions.save { id, definition }` → `{ file, listing }` (refuses to overwrite). Draft and save are rate-limited to 10 a minute. Demo mode reports no folder and fetches or writes nothing.

## Consequences

The renderer cannot touch the filesystem, network (beyond map tiles allowed by CSP) or child processes; every capability is an IPC action with a schema.
