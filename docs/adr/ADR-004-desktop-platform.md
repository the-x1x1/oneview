# ADR-004 — Desktop platform: Electron + Vite + React, Windows x64 first

Status: Accepted · 2026-09-21 · Package: `apps/desktop`, `@worldview/ipc-contract`

## Decision

- Electron (current stable) with `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, strict CSP, no `eval`, no remote module. Main process hosts the runtime (providers, state, history, offline, cameras, updater); the renderer hosts React + the render adapters.
- IPC is an allowlisted, typed request catalogue (`WorldRequests`) and event catalogue (`WorldEvents`) in `@worldview/ipc-contract`; the preload exposes `window.worldview` implementing `WorldClient`. The same interface is implemented in-process for browser development and demo mode, so the shell never branches on platform.
- Secrets use Electron `safeStorage` (DPAPI on Windows) via `credentials.set`; the renderer never receives values.
- Packaging: electron-builder → `WorldView-Setup-x.y.z.exe` (NSIS) and `WorldView-Portable-x.y.z.zip`. Node 22 LTS, pnpm 10.28.0 pinned.
- Tests use Node's built-in `node:test` runner through `tsx` (zero framework dependencies; the same runner GEV uses), grouped by directory convention (`tools/dev/run-tests.mjs`).
- 2026-09-21 amendment (first-run state): whether the welcome flow has been completed is persisted settings state (`AppSettings.firstRunCompleted`), not renderer storage. The interface has no durable store of its own — `localStorage` is unavailable under the sandbox, is per-origin rather than per-installation, and would disagree with the settings file after a reset or a portable/installed switch — so `finishWelcome()` writes through `settings.set` like every other preference and the runtime remains the single source of truth.
- 2026-09-23 amendment (memory in Diagnostics): `DiagnosticsSnapshot` gains an optional `memory` (`MemorySnapshot`: working set per process kind from Electron's `app.getAppMetrics()`, the main process's JS heap, and the totals of the last six hours at one sample per ten minutes). The main process samples it (`memory-monitor.ts`) and writes each sample to the application log as `process memory`; a runtime without process metrics leaves it out. The QA checklist's "memory in Diagnostics is stable" could not be checked before this.
- 2026-09-23 amendment (watch-zone quiet hours): `WatchZone` gains an optional `quietHours` (`{ start, end }`, "HH:MM" in this machine's time zone; `start` after `end` spans midnight). During them a zone's hits raise their events and feed items as before but interrupt — toast, desktop notification — only at SEVERE or above (`mayInterrupt`). The runtime now also honours `notifications.inApp`, which it had ignored.
- 2026-09-23 amendment (watch-zone escalation): `WatchZone` gains an optional `desktopMinimumSeverity` — desktop notifications only from that severity up, in-app and the feed keep the rest. The evaluator also re-notifies inside its 6 h dedupe window when the same subject comes back more severe than it was last notified at (a watch upgraded to a warning), titled "— now Severe" with `escalatedFrom` in the entry event's properties.
- 2026-09-23 amendment (pack signatures): `WorldPackSummary` gains an optional `signature` (`WorldPackSignatureSummary`: `unsigned | signed | trusted | unchecked | invalid`, the key id, the publisher's name, a reason) and `OfflineStatus` an optional `trust` (`requireTrusted` and the publishers' names, key ids and dates — never their keys). Four requests manage it: `offline.trustPublisher` (the signer of an installed, verified pack, under a name the operator types), `offline.importPublisher` (a `.worldpack-pub` file through the open dialog, read and parsed in the main process), `offline.removePublisher` and `offline.setRequireTrusted` (ADR-007). `WorldPackSummary` also gains optional `createdAt` and `expiresAt` from the manifest, so Settings can say how old a pack is and when its publisher says it goes out of date.
- 2026-09-23 amendment (raster overlays): request `overlays.list` (`RasterOverlay[]` from every running provider) and event `overlays.changed` (`{ overlays }`, the full list on any change). The store keeps them in `sources.overlays`; the map host hands them to the renderer host, which replays them into whichever renderer is active and any built later (ADR-008).
- 2026-09-24 amendment (connector definitions, for phase `source-health-ui`): requests `sources.definitions.list` (`DefinitionsListing`: the operator's folder, or null without one, and every definition file with its id, connector, enabled state, whether it is shipped, and its problems and notes), `sources.definitions.reload` (the listing plus the ids added, removed and restarted), `sources.definitions.setEnabled { file, enabled }` (persisted as `sources.setEnabled` is), `sources.definitions.openFolder` (main opens the runtime's folder with `shell.openPath`; the path never comes from the renderer), `sources.definitions.draft { url }` → `DefinitionDraft` (`definition`, `connector`, `notes`, `todo`, `validation`; the fetch runs in main) and `sources.definitions.save { id, definition }` → `{ file, listing }` (refuses to overwrite). Draft and save are rate-limited to 10 a minute. Demo mode reports no folder and fetches or writes nothing.
- 2026-10-05 amendment (the nearest place, offline): request `search.nearest` `{ position, kinds?, limit?, maxDistanceM? }` → `NearbyPlaceResult[]`, nearest first — each place with `distanceM` and `bearingDeg`, where the point lies from it on the WGS84 ellipsoid ("23 km NNE of Hilo"). Answered in memory from the gazetteers search already uses (the built-in list and the bundled Natural Earth countries, regions and cities; `Gazetteer.nearest?`, optional, in `@worldview/query-engine`); nothing is sent anywhere. An installed worldpack's places within 100 km are asked too (`PlaceSearcher.nearest?` in `@worldview/offline`: the in-memory index scans its entries, the SQLite one the box round the point by each entry's stored position). Cities when no kind is given; at most 10. Validated in `ipc-schemas.ts`; the demo client answers from its recorded places. First user: What's here (a right-click on the map).
- 2026-10-05 amendment (the sky overhead): request `sky.overhead` `{ observer, minElevationDeg?, limit? }` → `SkyOverheadAnswer` — the satellites above the observer's horizon now, highest first (`SkySatellite`: azimuth, elevation, range, height, category, and whether the Sun lights it, by a cylindrical shadow), how many there are, and the Sun's altitude there. Worked out by the runtime from the live world's satellites (`runtime/support/sky-overhead.ts`): each one's propagated position carried to now along the chord to its `nextPosition`, as the globe moves its marker, then look angles on the WGS84 ellipsoid; nothing is looked up. −5° to 90° minimum (0 when not said), 1–500 (200 when not said). Validated in `ipc-schemas.ts`; the demo client answers with look angles of its recorded satellites. First user: the Sky tab.
- 2026-10-05 amendment (a collection's places as geodata): `collections.export` gains an optional `format` — `json` (the default, the collection file as before), `gpx` (GPX 1.1 waypoints), `kml` (KML 2.2 placemarks) or `geojson` (points) — and its answer optional `places` and `skipped` counts. The geodata formats write only items with a position: the operator's own always; a collected object only while it is in the world and every provider behind it allows export (`mayExport`, the rule `export.objects` keeps), with those providers' attribution in the file's metadata. The collection file applies the same rule: a collected object whose sources do not allow export (or that is no longer in the world) is written by its title and id without its position, and `skipped` counts it. Validated in `ipc-schemas.ts`; the browser demo writes the collection file only. `collections.import` (unchanged in shape) also reads a `.gpx`, `.kml` or `.geojson` file as a new collection of its points (the files connector's GPX and KML readers, so `@worldview/runtime` now depends on `@worldview/connector-runtime`), id `places-<file name>`, items dated by the file's own times or else the file's modification time so a second import of the same file is recognised; lines and shapes are counted in `issues`, not kept; at most 2,000 places and 20 MB.
- 2026-10-05 amendment (the measured line to a file): request `export.line` `{ points (2–500), closed?, name?, format: gpx | kml | geojson }` → `{ path, points } | { cancelled }`: a GPX route (a closed shape is a route back to its start; GPX has no shapes), a KML LineString or Polygon, or a GeoJSON LineString or Polygon. The points are the operator's own clicks, so no source's data policy applies. Validated in `ipc-schemas.ts`; the browser demo writes nothing.
- 2026-10-05 amendment (watch zones as shapes): requests `watchzones.export` `{ format: kml | geojson }` → `{ path, zones, skipped } | { cancelled }` (a circle as a 72-point polygon, GeoJSON also keeping `circle: { center, radiusM }`; an admin region without bounds skipped) and `watchzones.import` (no request) → `{ zones: Array<{ name, geometry }>, issues }`: drafts only, read from a KML or GeoJSON file's polygons (outer rings; each part of a multipolygon its own draft; a WorldView circle back as a circle; points, lines, rings across 180° and bad rings counted in `issues`; at most 200). The interface saves each draft with the event types a new zone gets (`watchzones.save`), so the runtime decides nothing about what a zone listens for. Validated in `ipc-schemas.ts`; the browser demo has no file picker and says so.
- 2026-10-05 amendment (objects as KML): `export.objects` gains `format: 'kml'` — objects with a position as KML 2.2 placemarks, a folder per type, named as the map names them, dated by `observedAt`, at their altitude when they have one, with the sources' attribution in the document — under the same per-provider export gate as the other formats.
- 2026-10-05 amendment (a track as GPX or KML): `export.track` gains `format: 'gpx' | 'kml'` — a GPX 1.1 track (one segment, each point's time and, where recorded, elevation) or a KML LineString at its altitudes spanning the track's times — under the same refusal rule as GeoJSON and CSV.
- 2026-10-05 amendment (satellite pass alerts): `AppSettings.passAlerts?` — `{ satellites: Array<{ objectId, name }> (≤ 20), leadMinutes (1–60), visibleOnly, desktop }`, optional and additive (validated in `@worldview/config`). The runtime (support/pass-alerts.ts) asks each listed satellite's sources for passes over the home view (`objectDetails`, the same answer `world.details` gives) shortly after start, every 20 minutes and on every settings change; schedules a notice `leadMinutes` before each rise within three hours (visible passes only when `visibleOnly`); announces each pass once, through the `notification` event and, when `desktop`, the host's Windows notification. No home view, no alerts: WorldView never looks up where the operator is.

## Consequences

The renderer cannot touch the filesystem, network (beyond map tiles allowed by CSP) or child processes; every capability is an IPC action with a schema.
