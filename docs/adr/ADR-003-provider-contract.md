# ADR-003 — Provider contract and runtime isolation

Status: Accepted · 2026-09-21 · Packages: `@worldview/provider-sdk`, `@worldview/provider-runtime`, `@worldview/source-health`

## Decision

- A provider is `manifest + data policy + normalizer + fixtures + tests`. `ProviderManifest` carries capabilities, credentials (keys only), `RefreshPolicy`, mandatory `ProviderDataPolicy`, attribution, `commercialReview` and an `allowedHosts` allowlist.
- Providers reach the world only through `ProviderContext` (http, sockets, credentials.has, cache, settings, local access, hash, clock, logger). No direct fetch/fs/child_process/WebSocket.
- `ProviderHost` owns scheduling, timeouts, bounded retries, exponential backoff, host allowlists, client-side rate limiting, per-host circuit breakers (in the shared `HttpClient`), observation admission (schema-validated, providerId-checked, batch-capped) and health publication into `SourceHealthRegistry`. One provider failure never leaves its health entry.
- Malformed bodies are invalidated in the HTTP cache so they are never served as a stale fallback; last-good data lives in world state, which ages it by policy instead of re-serving it.
- 2026-09-21 amendment (runtime composition): secrets stay out of provider code in the two remaining shapes — `ProviderHttpRequest.credential.as` gained `'path'` (the provider builds a `{TOKEN}` placeholder URL and the `HttpClient` substitutes the percent-encoded secret into that path segment; NASA FIRMS uses it), and `ProviderSockets.open` gained `opts.credential`, whose resolved secret reaches the provider only as `ProviderSocketEvents.onOpen(ctx.secret)` for the handshake frame (AISStream uses it; the secret is never attached to the socket handle).
- 2026-09-23 amendment (camera keys): `ProviderHttpRequest.credential.as` gained `'xml-body'` for APIs that take the key inside a POST body (Trafikverket's `<LOGIN authenticationkey="…"/>`). The provider builds the body with a `{NAME}` placeholder; the `HttpClient` substitutes the XML-escaped secret, and refuses to send a body without the placeholder. The provider host now also scopes each provider's HTTP credential resolver to the keys its manifest declares, as sockets already did.
- 2026-09-23 amendment (a host the user names): `ProviderManifest.trustedHostSetting` — local transports only (`local-process`, `hardware`) — names one of the provider's `string` settings in which the user types one more host, such as a receiver elsewhere on the LAN. The provider host keeps that setting's value (lowercased, a DNS name or IPv4 address, no wildcards) as the provider's trusted host: the HTTP client allows exactly that host, over plain HTTP as loopback is, and `local.probeLocal` may probe it; an empty or invalid value adds nothing, and a change applies to the next request. `readsb-local`'s "Receiver on another machine" setting promised this and nothing honoured it — the client's allowlist was the manifest's loopback pair, so a LAN receiver was refused with HOST_NOT_ALLOWED.
- 2026-09-23 amendment (local-sensor kit, roadmap 0.5): `@worldview/provider-sdk` gained `local-device.ts` — additive, no existing type changed. `resolveLocalEndpoint` is the one endpoint policy for local sources (http(s) to loopback, or exactly the host named in the `trustedHostSetting`; never credentials in the URL), `LocalDeviceDetector` the one conservative detection (probe the configured endpoint before polling, OFFLINE "<device> not detected at <url>" with a back-off, back to probing after a transport failure; nothing is discovered), and `stringSetting` / `numberSetting` read settings the same way everywhere. `readsb-local` moved onto them with its messages unchanged; `weatherlink-local` (a Davis WeatherLink Live, `transport: 'hardware'`, off by default) is the first source built on them.
- 2026-09-23 amendment (line streams): `ProviderLocalAccess.openLineStream?(target, events, opts)` — optional, additive — opens an outbound TCP connection to loopback in `manifest.allowedHosts` or exactly the provider's trusted host and delivers it line by line (LF-split, trailing CR dropped); a line over `maxLineBytes` (default 1,024) or past the runtime's rate cap (500 a second) is dropped and counted in `handle.dropped`. Refusals are typed: HOST_NOT_ALLOWED, OFFLINE (nothing listening), DNS, TIMEOUT, NETWORK. Nothing ever listens. `testing.FixtureLocalAccess` records streams (`simulateLine/Close/Error`), and the contract checklist can feed `subscription.lines`. First user: `ais-local` (NMEA 0183 AIVDM from the user's own AIS receiver).
- 2026-09-23 amendment (view centre): `ProviderQuery.center?` — optional, additive — is where the view is centred, passed with `bounds` to bounds-query providers (the renderer sends it with `world.viewport`, whose request gained an optional `center`). The middle of the bounds is not it: a globe-wide view's bounds are the whole world, whose middle is 0°, 0°. `adsb-lol` used exactly that as its one 250 nm disc, so a zoomed-out map asked for the Gulf of Guinea and showed no aircraft. The provider host also polls early when the centre moves by more than a degree under unchanged bounds.
- 2026-09-23 amendment (raster overlays, for phase `ogc`): `WorldProvider.overlays?(): Promise<RasterOverlay[]>` — optional, additive. The host asks once after `start()` and again on `ProviderHost.refreshOverlays(providerId)`, validates every descriptor with `rasterOverlaySchema`, sets its `providerId` to the manifest's whatever it said, refuses one whose tile host (`overlayHost`) is not among `manifest.allowedHosts` (the same allow-list the HTTP client enforces, so a provider cannot point the renderer at a host it may not reach itself), drops duplicates and anything past 32, and publishes the full list of every running provider through `onOverlays` / `overlays()`; a stopped or disabled provider's overlays go away with it. Overlays are https only (the renderers fetch the tiles; the CSP allows https images). A connector definition never holds one: the `ogc` connectors derive them from a service's capabilities.
- The contract checklist (`pnpm provider:test <dir>`, 16 checks) is the completion definition; its JSON report is release evidence. The manifest's data policy must equal the legal registry record in `config/licenses/providers.json`.

## Consequences

Adding a provider touches `providers/<id>/` (+ fixtures, + registry record) only. UI and renderers never import providers (enforced by boundary tests).
