# ADR-003 — Provider contract and runtime isolation

Status: Accepted · 2026-09-21 · Packages: `@worldview/provider-sdk`, `@worldview/provider-runtime`, `@worldview/source-health`

## Decision

- A provider is `manifest + data policy + normalizer + fixtures + tests`. `ProviderManifest` carries capabilities, credentials (keys only), `RefreshPolicy`, mandatory `ProviderDataPolicy`, attribution, `commercialReview` and an `allowedHosts` allowlist.
- Providers reach the world only through `ProviderContext` (http, sockets, credentials.has, cache, settings, local access, hash, clock, logger). No direct fetch/fs/child_process/WebSocket.
- `ProviderHost` owns scheduling, timeouts, bounded retries, exponential backoff, host allowlists, client-side rate limiting, per-host circuit breakers (in the shared `HttpClient`), observation admission (schema-validated, providerId-checked, batch-capped) and health publication into `SourceHealthRegistry`. One provider failure never leaves its health entry.
- Malformed bodies are invalidated in the HTTP cache so they are never served as a stale fallback; last-good data lives in world state, which ages it by policy instead of re-serving it.
- 2026-09-21 amendment (runtime composition): secrets stay out of provider code in the two remaining shapes — `ProviderHttpRequest.credential.as` gained `'path'` (the provider builds a `{TOKEN}` placeholder URL and the `HttpClient` substitutes the percent-encoded secret into that path segment; NASA FIRMS uses it), and `ProviderSockets.open` gained `opts.credential`, whose resolved secret reaches the provider only as `ProviderSocketEvents.onOpen(ctx.secret)` for the handshake frame (AISStream uses it; the secret is never attached to the socket handle).
- 2026-09-23 amendment (camera keys): `ProviderHttpRequest.credential.as` gained `'xml-body'` for APIs that take the key inside a POST body (Trafikverket's `<LOGIN authenticationkey="…"/>`). The provider builds the body with a `{NAME}` placeholder; the `HttpClient` substitutes the XML-escaped secret, and refuses to send a body without the placeholder. The provider host now also scopes each provider's HTTP credential resolver to the keys its manifest declares, as sockets already did.
- 2026-09-23 amendment (a host the user names): `ProviderManifest.trustedHostSetting` — local transports only (`local-process`, `hardware`) — names one of the provider's `string` settings in which the user types one more host, such as a receiver elsewhere on the LAN. The provider host keeps that setting's value (lowercased, a DNS name or IPv4 address, no wildcards) as the provider's trusted host: the HTTP client allows exactly that host, over plain HTTP as loopback is, and `local.probeLocal` may probe it; an empty or invalid value adds nothing, and a change applies to the next request. `readsb-local`'s "Receiver on another machine" setting promised this and nothing honoured it — the client's allowlist was the manifest's loopback pair, so a LAN receiver was refused with HOST_NOT_ALLOWED.
- 2026-09-23 amendment (local-sensor kit, roadmap 0.5): `@worldview/provider-sdk` gained `local-device.ts` — additive, no existing type changed. `resolveLocalEndpoint` is the one endpoint policy for local sources (http(s) to loopback, or exactly the host named in the `trustedHostSetting`; never credentials in the URL), `LocalDeviceDetector` the one conservative detection (probe the configured endpoint before polling, OFFLINE "<device> not detected at <url>" with a back-off, back to probing after a transport failure; nothing is discovered), and `stringSetting` / `numberSetting` read settings the same way everywhere. `readsb-local` moved onto them with its messages unchanged; `weatherlink-local` (a Davis WeatherLink Live, `transport: 'hardware'`, off by default) is the first source built on them.
- 2026-09-23 amendment (line streams): `ProviderLocalAccess.openLineStream?(target, events, opts)` — optional, additive — opens an outbound TCP connection to loopback in `manifest.allowedHosts` or exactly the provider's trusted host and delivers it line by line (LF-split, trailing CR dropped); a line over `maxLineBytes` (default 1,024) or past the runtime's rate cap (500 a second) is dropped and counted in `handle.dropped`. Refusals are typed: HOST_NOT_ALLOWED, OFFLINE (nothing listening), DNS, TIMEOUT, NETWORK. Nothing ever listens. `testing.FixtureLocalAccess` records streams (`simulateLine/Close/Error`), and the contract checklist can feed `subscription.lines`. First user: `ais-local` (NMEA 0183 AIVDM from the user's own AIS receiver).
- 2026-09-23 amendment (view centre): `ProviderQuery.center?` — optional, additive — is where the view is centred, passed with `bounds` to bounds-query providers (the renderer sends it with `world.viewport`, whose request gained an optional `center`). The middle of the bounds is not it: a globe-wide view's bounds are the whole world, whose middle is 0°, 0°. `adsb-lol` used exactly that as its one 250 nm disc, so a zoomed-out map asked for the Gulf of Guinea and showed no aircraft. The provider host also polls early when the centre moves by more than a degree under unchanged bounds.
- 2026-09-23 amendment (raster overlays, for phase `ogc`): `WorldProvider.overlays?(): Promise<RasterOverlay[]>` — optional, additive. The host asks once after `start()` and again on `ProviderHost.refreshOverlays(providerId)`, validates every descriptor with `rasterOverlaySchema`, sets its `providerId` to the manifest's whatever it said, refuses one whose tile host (`overlayHost`) is not among `manifest.allowedHosts` (the same allow-list the HTTP client enforces, so a provider cannot point the renderer at a host it may not reach itself), drops duplicates and anything past 32, and publishes the full list of every running provider through `onOverlays` / `overlays()`; a stopped or disabled provider's overlays go away with it. Overlays are https only (the renderers fetch the tiles; the CSP allows https images). A connector definition never holds one: the `ogc` connectors derive them from a service's capabilities.
- 2026-09-23 amendment (a folder the user names, for phase `files`): `ProviderManifest.grantedFolderSetting` — filesystem transport only — names one of the provider's `string` settings in which the user types one folder on this computer (an absolute path in Windows, POSIX or UNC spelling; never a drive or filesystem root; no `..`). The provider host keeps that folder as the provider's grant (`isGrantableFolder`; a change applies to the next read) and hands the runtime a function answering it; `createLocalAccess` resolves every `readGrantedFile` inside the folder current at the call, falling back to the bundled resources grant when the setting names nothing. `ProviderLocalAccess.statGrantedFile?(path)` — optional, additive — answers size and mtime under the same rules (a directory or a missing file is refused), so a file provider can poll for change without reading; `testing.FixtureLocalAccess` gains it with per-path `mtimes`.
- 2026-09-23 amendment (the granted folder made real, and ogr2ogr, for phase `files`): `checkRelativePath` / `extensionOf` (`provider-sdk/local-files.ts`) are the one path rule for a file inside a granted folder — relative, `/`-separated, nothing that could leave it (absolute, drive, UNC, `..`, `:`, Windows-reserved names) — applied by connectors when a definition is validated and by the host before every read. The runtime's `readGrantedFile` / `statGrantedFile` then resolve the folder's and the file's real paths (links and junctions followed) and refuse anything not strictly inside (HOST_NOT_ALLOWED), anything but a regular file (UNSUPPORTED; a FIFO would block the poll), a file over the cap before a byte is read (TOO_LARGE), and a file replaced between the check and the open. A provider that declares `grantedFolderSetting` reads only the folder the user named — nothing at all while the setting is empty, never the bundled resources — and gets `ProviderLocalAccess.ogr2ogr?: Ogr2ogrAccess`: `detect()`, `datasetStat(input)` (a shapefile is its parts, a `.gdb` its files, each checked inside the grant) and `toGeoJson({ input, layer?, timeoutMs?, maxOutputBytes?, signal? })`, which runs the user's own `ogr2ogr` (found on PATH; `.exe` on Windows; never installed or bundled, §141) with a fixed argument list, no shell, a minimal environment (no `WORLDVIEW_`/`ONEVIEW_` variables) and a fresh temporary directory always removed; inputs are limited to self-contained formats (`OGR_INPUT_EXTENSIONS`; VRT and friends, which can point elsewhere, are refused by name), layer names to `OGR_LAYER_NAME`. `testing.FixtureLocalAccess` answers as the host does (the path rule, UNSUPPORTED for a missing file, TOO_LARGE over `maxBytes`), counts reads and stats, can refuse (`refuseFiles`), and takes a `testing.FixtureOgr2ogr` stand-in.
- 2026-09-23 amendment (a poll's budget, and when overlays are asked for; from phases `arcgis`, `ogc` and `stac`): `RefreshPolicy.pollBudgetMs?` — optional, additive — is the time one poll may take when a poll is more than one request (pages); absent, the host's budget stays `timeoutMs × (maxRetries + 1) + 5 s`, which had been the whole budget for a 200-page poll (`pollBudgetMs()` in the host). The host no longer awaits a provider's first `overlays()` in `startProvider` — one enabled overlay source on a slow or unreachable service had held up the application's start by up to its request timeout — and asks again after every successful poll of a provider that implements `overlays()` (unchanged lists are dropped), so a first read that failed, or a changed setting, reaches the renderers without a restart.
- 2026-09-23 amendment (the response cache, from phase `stac`): the HTTP client's in-memory response cache is bounded (`cacheMaxEntries`, 256 by default; the least recently stored entry goes first). It had no eviction, so a GET source whose URL changes each poll — a rolling time window, a bounds-driven definition as the view moves — added an entry per distinct URL for the life of the process.
- 2026-09-23 amendment (telemetry, for phase `telemetry`): `ProviderManifest.telemetry?: TelemetryDescriptor` — optional, additive, data only — names the numeric payload keys worth plotting over time: `{ series: [{ key, name, units?, format?, min?, max?, limits?: { warnLow?, warnHigh?, critLow?, critHigh? } }] }`, at most 32 series, unique keys, `format` from a fixed set (`TELEMETRY_FORMATS`: `number:0–2`, `percent`, `celsius`, `hpa`, `mps`, `kmh`, `degrees`, `ugm3`, `ppm`, `volts`, `dbm`) and never a format string, limits in order (`critLow ≤ warnLow ≤ warnHigh ≤ critHigh`). Payload values stay SI; the descriptor labels, it never converts. The type and schema live in `provider-sdk/telemetry.ts` because the manifest carries them; `@worldview/telemetry` (a new package, the phase's) re-exports them. The renderer reads the descriptor through `providers.list`.
- 2026-09-23 amendment (the one listener, for phase `ingest`): `ProviderLocalAccess.listen?(options, handler)` — optional, additive, and offered only to a `local-process` provider — opens an HTTP/1.1 listener on `127.0.0.1` (fixed by the runtime; the provider names `port` 1024–65535 and one `/`-rooted `path`) and hands the provider every `POST` there that carries the bearer token named by `options.credential.key`, compared by the runtime against the credential store per request (`bearerMatches`, length-only timing) and stripped, with cookies, before the provider sees the request. Refused before the provider is asked: a non-loopback peer (403), a `Host` that is not `127.0.0.1`/`localhost` with the listener's port (421 — DNS rebinding), another path (404), another method (405, `OPTIONS` included, so no CORS preflight passes), a missing or wrong token (401), a body over `maxBodyBytes` (1 MiB default, 16 MiB at most; 413, checked from `Content-Length` and while reading), more than `maxRequestsPerMinute` (600 default; 429 with `Retry-After`). One listener per provider, for a credential its manifest declares; the host closes it when the provider stops or is disabled. A port in use is NETWORK with the port named. `ListenerGate` and `checkListenerOptions` (`provider-sdk/local-listener.ts`) are the rules both the runtime (`runtime/support/local-listener.ts`) and `testing.FixtureLocalAccess` (`listen`, `simulateRequest`, `listenerSecrets`) apply. This is the first thing WORLDVIEW listens on besides the camera relay; the threat model has it as T16.
- 2026-09-23 amendment (a socket credential in the URL, for phase `traccar`): `ProviderSocketOptions.credential` gains `as?: 'open' | 'query'` and `param?`. `open` (the default) is what it was — the secret resolved by the host and handed to `onOpen(ctx.secret)` for the first frame. `query` has the host resolve the secret and append it to the URL it dials as `<param>=<secret>` (`token` by default; the name must be a plain identifier), and `onOpen` gets no secret: the provider never builds, sees, logs or reports a URL that carries it, and the host puts the dialed URL in no log line or error. `testing.FixtureSockets` does the same, recording the dialed URL.
- 2026-09-23 amendment (MQTT, for phase `mqtt`): `ProviderContext.mqtt?: ProviderMqtt` — optional, additive, and only on a provider whose transport is `local-process` or `hardware`. `connect({ host, port?, tls?, username?, credential?, clientId?, subscriptions, maxPayloadBytes?, maxMessagesPerSecond?, keepAliveSeconds?, connectTimeoutMs?, signal? }, events)` subscribes to topics on a broker at loopback in `manifest.allowedHosts` or exactly the provider's trusted host, outbound only, and never publishes. The runtime speaks MQTT 3.1.1 itself (`runtime/support/mqtt-packets.ts`, `mqtt-client.ts`; no client library, per §141): CONNECT with the username as given and the password resolved by credential key through the provider's own scoped resolver (never handed to the provider), SUBSCRIBE at QoS 0 or 1 (`#`/`+` filters validated), PUBACK for QoS 1, keep-alive pings with a dead-broker timeout, DISCONNECT on close. Each PUBLISH reaches `onMessage(topic, payload, { retained, qos })` as bytes; a payload over `maxPayloadBytes` (256 KiB default), a message past `maxMessagesPerSecond` (500 default) and any QoS 2 delivery are dropped and counted on the handle; a malformed stream, a refused CONNACK (AUTH for bad credentials, NETWORK otherwise), a refused subscription (AUTH) and nothing listening (OFFLINE) are typed. `testing.FixtureMqtt` / `FixtureMqttConnection` drive a provider from tests.
- The contract checklist (`pnpm provider:test <dir>`, 16 checks) is the completion definition; its JSON report is release evidence. The manifest's data policy must equal the legal registry record in `config/licenses/providers.json`.
- 2026-09-24 amendment (listener health, A3 of phase `ingest`): the host republishes a provider's health within a second (coalesced) after its loopback listener refuses a request before the provider is asked, and after one of its credentials changes when the provider has no `query` to reschedule. The `listen` factory the host is given takes an `onRefused(status)` observer.

## Consequences

Adding a provider touches `providers/<id>/` (+ fixtures, + registry record) only. UI and renderers never import providers (enforced by boundary tests).
